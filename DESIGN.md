# DESIGN — NOI Creative Website

**Status:** Visual implementation specification  
**Visual source of truth:** Approved Figma file  
**Secondary references:** Home, Nosotras and Contacto screenshots  
**Reference viewport:** 1440 px  
**Minimum supported width:** 320 px

---

## 1. Purpose

This document defines the visual rules that must remain consistent across the NOI Creative website.

It does not replace Figma. It translates the approved visual language into implementation constraints so that a coding agent can reproduce the design without improvising new patterns.

When a precise measurement is available in Figma, Figma wins. When a value is not available, use the design tokens and rules in this document.

---

## 2. Visual direction

The website uses an editorial, expressive and warm visual identity.

Core characteristics:

- Strong oversized typography.
- Mixed-font phrases.
- Warm cream and yellow surfaces.
- Deep blue and burgundy high-contrast sections.
- Orange emphasis and actions.
- Light-blue supporting surfaces.
- Rounded cards and image frames.
- Organic scallops, curves and irregular decorative forms.
- Photography combined with illustration.
- Controlled asymmetry.
- Clear narrative sections.
- Visual personality without compromising readability.

The implementation must not become:

- Generic SaaS design.
- Minimalist to the point of removing decoration.
- Corporate blue-and-white branding.
- Overly polished with glassmorphism.
- Tailwind-like utility composition.
- A reinterpretation of the approved design.

## 5. Typography

### 5.1 Font families

```scss
:root {
  --font-sans: "Satoshi", sans-serif;
  --font-display-accent: "Panel Sans", sans-serif;
  --font-serif: "Playfair Display", serif;
}
```

The actual CSS variable names generated by `next/font` may differ, but semantic aliases must remain.

### 5.2 Satoshi

Satoshi is the default site typeface.

Use it for:

- Headlines.
- Body copy.
- Navigation.
- Buttons.
- Links.
- Form labels.
- Form inputs.
- Metadata.
- Eyebrows.
- Captions.

### 5.3 Panel Sans

Panel Sans is a display accent.

Use it:

- Inside mixed-font headings.
- For a highlighted phrase that begins in Satoshi.
- Only where the design explicitly shows that treatment.

Do not:

- Use Panel Sans for full body paragraphs.
- Use it for navigation or form controls.
- Use it as a generic alternative heading font.

### 5.4 Playfair Display

Use Playfair Display for:

- Quote body copy.
- Editorial italic emphasis.
- Highlight phrases where Panel Sans is not used.
- Approved script-like typographic moments.

Do not use it for long general body copy.

### 5.5 Weight rule

Load only the weights visible in Figma.

Recommended mapping until verified:

```text
Body: 400–500
Navigation and labels: 500–600
Buttons: 600–700
Section headings: 600–800
Hero headings: 700–900
Playfair emphasis: 500–700 italic
```

These are implementation defaults only. Exact Figma weights take precedence.

## 6. Fluid type scale

Use `clamp()` for major responsive sizes.

Initial token proposal:

```scss
:root {
  --font-size-xs: clamp(0.72rem, 0.69rem + 0.12vw, 0.8rem);
  --font-size-sm: clamp(0.82rem, 0.78rem + 0.16vw, 0.94rem);
  --font-size-base: clamp(0.95rem, 0.9rem + 0.2vw, 1.06rem);
  --font-size-md: clamp(1.08rem, 1rem + 0.35vw, 1.32rem);
  --font-size-lg: clamp(1.35rem, 1.15rem + 0.85vw, 1.95rem);
  --font-size-xl: clamp(1.85rem, 1.45rem + 1.65vw, 3rem);
  --font-size-2xl: clamp(2.5rem, 1.7rem + 3.2vw, 5rem);
  --font-size-hero: clamp(3.25rem, 1.8rem + 5.7vw, 7.5rem);
}
```

### Usage intent

```text
xs: legal text, minor captions
sm: labels, metadata, eyebrow
base: body copy
md: lead paragraph
lg: small section title
xl: standard section heading
2xl: major section heading
hero: oversized editorial headline
```

### 1440 px line-break rule

At 1440 px:

- Preserve approved Figma line breaks.
- Use controlled `<span>` blocks or desktop-only break opportunities where required.
- Do not insert `<br>` elements into general body copy.
- Controlled hero line breaks may be disabled below desktop.
- Fluid type must not change the approved 1440 px wrapping.

  --space-8: 4rem;
  --space-9: 6rem;

## 14. Grid principles

### Desktop

- Use CSS Grid for primary section composition.
- Use flexbox for simple rows and controls.
- Maintain asymmetric editorial layouts where approved.
- Let imagery overlap only within an explicitly positioned composition wrapper.
- Do not absolutely position whole sections.

### Tablet

- Reduce column count.
- Preserve content reading order.
- Reposition decorative imagery.
- Avoid narrow body-copy columns.

### Mobile

- One semantic content column by default.
- Collages may remain layered inside a bounded wrapper.
- Decorative elements may be omitted.
- Images may change crop or order only when necessary.
- No horizontal overflow.

## 15. Header

### Desktop behavior

- Sticky header.
- Rounded pill shell.
- Logo on the left.
- Navigation links in the central area.
- “Hablemos” pill CTA on the right.
- CTA links to `/contacto`.
- Header spacing and dimensions must match Figma at 1440 px.
- Use a high but soft shadow.
- Do not make the header full-width edge-to-edge.

### Mobile behavior

- Sticky header.
- Logo remains visible.
- Menu trigger replaces desktop navigation.
- Menu opens as a dropdown below the header.
- CTA may be included inside the dropdown.
- Maintain cream/light shell treatment unless the approved mobile design later specifies otherwise.
- Do not use a full-screen takeover.
- Locking body scroll is unnecessary unless the dropdown becomes taller than the viewport.
- Menu transitions should be short and non-blocking.

## 16. Buttons

### Shared button anatomy

- Pill shape.
- Satoshi.
- Medium or semibold weight.
- Clear arrow or directional icon when approved.
- No generic rectangular buttons.
- Minimum usable touch height.
- Hover and focus states must remain within the brand palette.

### Recommended variants

```text
primary-orange
primary-burgundy
primary-yellow
secondary-outline
dark-outline
text-link
```

### Interaction rule

Use SCSS transitions for:

- Background.
- Text color.
- Border color.
- Small translate or scale.
- Icon movement.

Use Motion only when the button is part of a coordinated section animation.

## 17. Forms

### Contact form visual rules

- Dark navy card on cream background.
- Large rounded container.
- Two-column field layout on desktop.
- One-column layout on mobile.
- Labels use uppercase or tracked treatment where approved.
- Inputs appear integrated into the surface rather than generic white boxes.
- Underline or low-contrast border treatment must match Figma.
- Orange pill submit button.
- Consent checkbox remains clearly visible.
- Error text must be readable and must not shift the entire composition excessively.

### Field states

Required:

## 19. Organic shapes

The design uses:

- Scalloped section edges.
- Rounded arches.
- Large organic background forms.
- Scribbles and ribbon-like marks.
- Decorative cropped circles.
- Irregular collage masks.

## 20. Motion direction

Animations are important to the final identity, but their detailed choreography is not yet approved.

### Current implementation rule

- Build the static composition first.
- Achieve 1440 px fidelity before adding section animations.
- Add animation specifications in a later revision.
- Motion is the approved library.
- GSAP is excluded from the MVP.

### Motion character

Future motion should feel:

- Playful.
- Editorial.
- Deliberate.
- Smooth.
- Brand-specific.

It must not feel:

- Hyperactive.
- Bouncy by default.
- Like a generic landing-page preset.
- Delayed enough to hide content.
- Dependent on scroll-jacking.

### Performance constraints

- No non-essential animation before the LCP content is visible.
- Prefer transform and opacity.
- Avoid continuous animation on many large elements.
- Infinite carousel must pause or simplify for reduced motion.
- Do not animate large raster images in ways that trigger expensive repainting.

---

## 21. Responsive adaptation rules

### Global rule

The mobile design may be simplified, but it must remain recognizably the same brand and preserve the same narrative.

### Preserve at all sizes

- Brand colors.
- Font roles.
- CTA hierarchy.
- Content order.
- Main imagery.
- Section identity.
- Important decorative motifs where feasible.

### May simplify on smaller screens

- Secondary floating illustrations.
- Complex overlaps.
- Number of visible carousel items.
- Exact image rotation.
- Background decoration density.
- Multi-column timeline layouts.
- Exact desktop line breaks.

### Must never happen

- Horizontal scroll.
- Text over unreadable image regions.
- Tiny desktop composition scaled down.
- Cropped faces or essential project details.
- Hidden primary CTAs.
- Reordered content that changes meaning.
- Mobile-only visual style unrelated to desktop.

## 26. Accessibility-related visual rules

Even without a full WCAG project:

- Focus indicators must be visible.
- Form labels must remain visible.
- Error messages must use text and icon or structure, not color only.
- Decorative SVGs must not be announced.
- Body text must maintain readable size and line-height.
- Light-blue and yellow surfaces require ink or navy text.
- Cream-on-yellow combinations must be checked before approval.
- Reduced motion must preserve all information.

## 27. Agent implementation rules

When a language model implements the UI, it must:

1. Inspect the exact Figma frame through MCP.
2. Read the PRD and this document before writing code.
3. Identify reusable layout and UI patterns.
4. Create or update tokens before adding repeated raw values.
5. Use SCSS Modules.
6. Use Server Components by default.
7. Isolate Motion in small Client Components.
8. Use `next/image` for raster imagery.
9. Use supplied SVG assets instead of recreating them.
10. Preserve 1440 px line breaks and composition.
11. Adapt tablet and mobile according to the rules here.
12. Avoid adding unapproved packages.
13. Avoid making design changes under the label of “improvement”.
14. Mark missing content, SEO data and alt text with explicit TODOs.
15. Stop and request clarification when an approved page design is missing.

- 1280 px checked.
- 768 px checked.
- 390 px checked.
- 320 px checked.
