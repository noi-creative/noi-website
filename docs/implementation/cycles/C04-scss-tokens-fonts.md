## Scope

- Install `sass` as a dev dependency.
- Create the SCSS architecture under `src/styles/`:
  - `_breakpoints.scss` — Sass variables for breakpoints (compile-time only).
  - `_functions.scss` — reserved for future SCSS functions.
  - `_mixins.scss` — media-query helpers (`from`, `until`) and the `container` mixin. Uses `@use "breakpoints" as *`.
  - `_reset.scss` — minimal reset (no colour tokens here, only structural resets).
  - `_tokens.scss` — CSS custom properties as the runtime source of truth (primitive + semantic colors, font families, font weights, fluid type scale, line-height, tracking, spacing, layout, radii, shadows, borders, z-index, motion).
  - `_typography.scss` — base typography that consumes the tokens (font-family on `body`, default heading sizing, eyebrow helper, reduced-motion handling).
  - `index.scss` — entry that loads the partials in cascade order: `tokens` → `reset` → `typography`.
- Create `src/app/globals.scss` that `@use`s `../styles/index`. Delete the old `src/app/globals.css`.
- Create `src/app/fonts.ts`:
  - `satoshi` via `next/font/local` (weights 400, 500, 700, 900 — all four `.otf` files staged in C01).
  - `playfairDisplay` via `next/font/google` (weights 400, 500, 700; styles normal + italic — matches the C03 audit).
  - **Skip Panel Sans** — C03 confirmed it is not used in any approved frame. The `.otf` files stay on disk but are not loaded by `next/font/local`. A TODO is recorded in `STATUS.md` for Q01 if a future cycle introduces a Panel Sans moment.
- Update `src/app/layout.tsx` to import `./globals.scss` and the fonts, and to expose the font variables on the `<html>` element so the tokens can read them.
- Create a development-only fixture that proves the tokens, fonts and reduced-motion behaviour are wired correctly. **Not a permanent public route.** It is rendered inside the existing `src/app/page.tsx` placeholder (which C05 will replace). The fixture is documented and will be removed when C05 lands.
- Verify `npm run verify` end-to-end.
- Run `prettier --write` on the new SCSS / TS files to keep the tree conformant.

## Decisions

- **Token implementation:** CSS custom properties only, declared on `:root`. Sass variables only for breakpoints (compile-time). This is `ADR-002` and `IMPLEMENTATION_WORKFLOW.md` §C04.
- **SCSS module syntax:** modern `@use` / `@forward`. No `@import`. This is also `ADR-002`.
- **Token contents follow `DESIGN.md` exactly.** Values that the C03 audit flagged as "provisional" are kept at the `DESIGN.md` value with a `// TODO pending Figma MCP` comment where the audit specifically called them out. C04 does not invent new values; it does not lower the bar; it does not pre-empt Figma MCP.
- **Font variables exposed on `<html>`.** `next/font` writes the variable to a className that we attach to the `<html>` element. `tokens.scss` then reads those variables and exposes the semantic aliases (`--font-sans`, `--font-serif`, `--font-display-accent`) on `:root`. This honours `DESIGN.md` §5.1: "the actual CSS variable names generated by `next/font` may differ, but semantic aliases must remain".
- **Panel Sans deliberately not loaded.** C03 audit found zero Panel Sans moments in the approved Home, Nosotras or Contacto frames. Loading it would add to the LCP surface for no approved-page benefit. The `.otf` files stay on disk; a single line in `src/app/fonts.ts` documents how to load it later if needed.
- **Playfair Display weights:** `400, 500, 700` in `normal` and `italic`. This matches the C03 audit (`MIXED-FONT PHRASE PATTERN` and editorial-emphasis use cases). 600 is not loaded because no Figma moment needs it.
- **The placeholder home page (`src/app/page.tsx`) is temporarily enriched with a development fixture** that proves the tokens and fonts. It shows a small grid of swatches for the seven brand colours, a few type samples using the loaded fonts, and a reduced-motion note. C05 will replace it. It is **not** a permanent public route — it is the existing `Sitio en construcción` placeholder, made honest.
- **No raw colour values in the SCSS partials other than the token definitions.** Every consumer (reset, typography, fixtures) reads the token by name.
